## Запуск

Нужны Docker Engine / Docker Desktop и Compose v2. Команды выполняются в корне проекта:

```sh
cp .env.example .env
docker compose up -d --build
docker compose ps
```

Открыть **http://localhost:8000**. Описание API: http://localhost:8000/docs. Проверка сервера и соединения БД: http://localhost:8000/health.

| Логин | Роль | Пароль учебного стенда |
|---|---|---|
| admin | Администратор | DemoPass123! |
| dean | Деканат | DemoPass123! |
| teacher | Преподаватель № 1 | DemoPass123! |
| student | Студент № 1 | DemoPass123! |

Пароли предназначены только для локальной демонстрации. `web` опубликован на `127.0.0.1`; PostgreSQL доступна только внутри сети Docker. Для реального размещения нужны собственные учетные записи, HTTPS и `COOKIE_SECURE=true`.

Остановить с сохранением данных:

```sh
docker compose down
```

**Первичная схема и DML применяются только к пустому тому.** Пересборка приложения не запускает SQL повторно. `docker compose down -v` удаляет учебную БД целиком; для обычного запуска эта команда не нужна.

## Что реализовано

1. Четыре роли и серверная проверка принадлежности данных.
2. CRUD студентов, групп, преподавателей, дисциплин, назначений, работ, оценок и пользователей.
3. Промежуточные и семестровые работы, веса, шкалы 2–5 и зачет/незачет (1/0).
4. Ведомость группы по дисциплине, сводная ведомость студента, рейтинг, должники, статистика по группам/курсам/специальностям, качество знаний.
5. Excel, PDF и печать; русское меню, формы, таблицы, поиск и сортировка.
6. Журнал действий, архив прикладных данных, полное копирование и восстановление PostgreSQL.

Демонстрационный набор: **20 студентов, 5 групп, 15 дисциплин, 10 преподавателей, 15 назначений, 60 работ, 240 оценок**.

## Правила расчетов

- Итог: `round(sum(оценка * вес) / sum(вес))`, только если заполнены **все** работы назначения. PostgreSQL округляет положительные половины вверх.
- Например, `(5*1 + 3*2 + 4*2 + 5*5)/10 = 4.4`, итог **4**.
- Пустая работа — незавершенный итог, а не ноль. У зачета все работы должны быть сданы.
- Среднее считается по завершенным **балльным итогам дисциплин**, без зачетов, до двух знаков.
- Равные средние дают одинаковое место. Студент получает только свою строку рейтинга.
- Должники: завершенный итог 2 либо незачет 0. Пропуски отдельно видны в ведомости.
- Качество: доля студентов с назначениями в выбранном срезе, у которых все балльные итоги 4/5, все зачеты сданы, нет пропусков и есть хотя бы одна балльная дисциплина.
- Статистика по умолчанию включает все сохраненные периоды и учебные статусы. Назначение содержит год и семестр и позволяет сузить выборку.

Полные определения и особенности фильтров приведены в разделе 1.6 отчета.

## Тесты

Тесты рассчитаны на исходный учебный DML. Они временно создают записи и удаляют их по завершении. Не запускайте их на базе с настоящими данными.

```sh
docker compose exec -T web python -m pytest -q -p no:cacheprovider --junitxml=/tmp/results.xml
docker compose cp web:/tmp/results.xml docs/reports/test-results.xml
docker compose exec -T db psql -U progress -d progress -f /docker-entrypoint-initdb.d/03_checks.sql
```

Фактический повторный прогон 13.09.2026: **64 passed**, 46 именованных сценариев с параметризацией. Первый прогон выявил одну ошибку SQL-экранирования `%`; она исправлена. Проверка полного восстановления в отдельную БД вернула **240 оценок**. Заключительная проверка после сборки с зафиксированными зависимостями: также **64 passed** за 5,48 с; [результат](docs/reports/release-test-results.xml). Подробности, ограничения и ручной UI-чек-лист — в разделах 4–5 отчета.

## Резервные копии

```sh
sh scripts/backup.sh
```

Полная копия находится в `backups/*.dump` и исключена из Git. Восстановление **заменяет текущую базу**, поэтому сначала сохраните ее копию:

```sh
sh scripts/restore.sh backups/ИМЯ_КОПИИ.dump --confirm
```

Скрипт останавливает `web`, восстанавливает базу транзакционно и запускает приложение после успеха. При ошибке `web` остается остановленным. Кнопка «Архив» в браузере выгружает только учебные справочники и оценки в JSON; для полноценного восстановления нужен `.dump`.

## Структура

```text
app/
  main.py       # HTTP API, сессии и статика
  db.py         # Провайдер Dishka и транзакции
  schemas.py    # Типы и валидация
  service.py    # CRUD и права
  reports.py    # Расчеты и Excel/PDF
  security.py   # Пароли и токены
  static/       # HTML, CSS, JavaScript
sql/            # DDL, DML и контрольные запросы
tests/          # Интеграционные проверки
scripts/        # Backup, restore
```

Зависимости приложения указаны в `requirements.txt`; фактическое окружение успешного прогона — `requirements-lock.txt`. Docker устанавливает именно зафиксированный набор. Генерация отчета требует `python-docx`, генерация PNG/SVG — `sharp`; это вспомогательные инструменты, для запуска приложения они не нужны.
