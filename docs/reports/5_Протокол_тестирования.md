# 5 Протокол тестирования

## 5.1 Условия и фактический запуск

Дата выполнения — 13 сентября 2026 года. Проверки выполнялись на локальном Docker-стенде с реальными контейнерами web и PostgreSQL 17. Использованы Python 3.12, FastAPI 0.116.1, Dishka 1.6.0, psycopg 3.2.9 и pytest 8.4.1. Полный набор фактически установленных версий зафиксирован в requirements-lock.txt.

```
docker compose exec -T web python -m pytest -q \
  -p no:cacheprovider --junitxml=/tmp/results.xml
docker compose cp web:/tmp/results.xml docs/reports/test-results.xml
```

Итог повторного запуска: 64 проверок, 64 успешных, 0 ошибок; время pytest — 5.295 с. Это время выполнения тестов, а не показатель задержки HTTP или производительности приложения. Машиночитаемое свидетельство — docs/reports/test-results.xml. Проверки объемов SQL и восстановления копии сохранены отдельно.

## 5.3 Найденные дефекты

DEF01. При первоначальном запуске отчеты statistics и quality возвращали HTTP 500; связанный PDF-экспорт также не выполнялся. Причина: знак процента в SQL-псевдонимах «Успеваемость %» и «Качество %» драйвер psycopg воспринимал как начало параметра. Исправление: буквальные знаки процента экранированы как %% в тексте параметризованного SQL. Статус — исправлен и повторно проверен.

Первый прогон: 59 успешных проверок и 5 падений из 64. Падения относились к одному дефекту DEF01: два вида отчета, PDF, формула качества и срезы статистики. После исправления весь набор из 64 проверок прошел успешно. Разные тестовые падения не учитываются как пять независимых дефектов.

## 5.4 Проверка резервного копирования

BK01. Создана полная custom-копия базы командой pg_dump. Копия восстановлена pg_restore в отдельную временную базу progress_restore_check. Контрольный запрос SELECT count(*) FROM grades вернул 240. Рабочая база при проверке восстановления не заменялась. Временная база после проверки удалена. Статус — пройден; свидетельство — docs/reports/backup-check.txt.

## 5.5 Оценка качества и ограничения проверки

Автоматические проверки подтверждают основные CRUD-операции, права ролей, ограничения данных, расчет выбранных контрольных примеров, наличие шести отчетов и формирование файлов экспорта. Проверка BK01 подтверждает восстановление копии на текущем стенде. В браузере подтверждены сценарии, отмеченные в таблице 18; снимки сохранены в docs/screenshots.

Нагрузочное, длительное отказоустойчивое, межбраузерное и полное исследование безопасности не проводились. Печать через системный диалог и ручная проверка подтверждения изменения/удаления остаются пунктами приемки перед защитой. Успешный набор тестов не доказывает отсутствие всех возможных ошибок. Учебная защита, согласование документов преподавателем и публикация каждым участником на портале не являются выполненными программными тестами.
